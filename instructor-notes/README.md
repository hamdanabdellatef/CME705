# Instructor notes

## Delivery principles

- Begin each class with a question that can be answered by evidence.
- Ask students to predict an experiment before running it.
- Keep derivations connected to an executable NumPy example.
- Introduce PyTorch after students can explain the corresponding computation.
- Treat unsuccessful experiments as material for analysis, not as empty submissions.
- Review project feasibility early; data access and evaluation design usually constrain the project more than architecture choice.

## Before an offering

1. Run every linked script in a fresh environment.
2. Set dates and submission channels without editing stable assignment IDs.
3. Publish the academic-integrity and automated-tool policy for that cohort.
4. Review datasets, links, accessibility, and licensing.
5. Prepare assessment versions outside the public repository.

Historical grades, attendance, exams, student submissions, copied textbooks, and third-party teaching decks belong in private institutional storage.
